# Фонд студсовета — Telegram-бот

Бот для добровольных взносов на нужды студенческого совета КБГУ: общий фонд и отдельные
сборы, приём оплаты через ЮKassa, рейтинги участников, ежемесячные напоминания и
открытая отчётность о поступлениях и расходах.

> **Важно.** Приём реальных платежей выключен по умолчанию (`PAYMENTS_ENABLED=false`).
> Включайте его только после того, как согласованы получатель средств и правовая схема
> (см. «[Юридические ограничения](#юридические-ограничения)»). Всё остальное — сборы,
> отчётность, рейтинг, админка — работает и без платежей.

## Возможности (MVP)

| Раздел | Что есть |
| --- | --- |
| 💳 Внести взнос | Выбор общего фонда или проекта → произвольная сумма (или быстрые 100/300/500/1000 ₽) → экран с назначением платежа и получателем → защищённая страница ЮKassa → подтверждение в боте |
| 🎯 Наши сборы | Название, описание, цель, срок, собрано/потрачено, прогресс-бар, расходы по сбору |
| 🏆 Рейтинг | Топ-10 за календарный месяц (по Москве) и за всё время, своё место; анонимный показ по желанию |
| 📊 Отчётность | Сводка (поступления, возвраты, расходы, остаток), последние поступления, расходы с чеками, итоги по сборам |
| ⚙️ Настройки | Имя в рейтинге, анонимность, напоминания вкл/выкл, частота (раз в месяц / раз в 3 месяца), история своих взносов |
| 🛠 Админ-панель | Статистика, создание/закрытие сборов, расходы с чеками, участники и роли, CSV-выгрузка, рассылка, возвраты |

Не входит в первую версию (по ТЗ): автоплатежи, уровни и достижения, веб-панель, мультивалютность.

## Архитектура

```
Студент ─▶ Telegram ─▶ бот (aiogram 3, long polling) ──┐
                         │  планировщик (APScheduler)  ├─▶ PostgreSQL
ЮKassa ─▶ Nginx (HTTPS) ─▶ API (FastAPI, вебхуки) ─────┘
   ▲                                    │
   └──── создание платежей, проверка ◀──┘
```

Один репозиторий, два процесса (`bot` и `api`) с общим сервисным слоем:

```
app/
  config.py            настройки из .env
  money.py             разбор и форматирование сумм (копейки)
  db/                  модели SQLAlchemy 2, сессии
  services/            бизнес-логика без Telegram:
    payments.py          создание платежей, обработка статусов, возвраты
    yookassa.py          клиент API ЮKassa, проверка IP уведомлений
    stats.py             рейтинги, суммы, отчётность
    fundraisers.py, expenses.py, users.py, notifications.py, export.py
  bot/                 Telegram-интерфейс: handlers/, keyboards, тексты
  api/main.py          FastAPI: /yookassa/webhook/<секрет>, /health
  scheduler.py         напоминания, закрытие просроченных сборов, сверка платежей
migrations/            Alembic
tests/                 pytest (SQLite или PostgreSQL)
```

### База данных

`users`, `fundraisers`, `payments`, `refunds`, `expenses`, `admins`, `notification_logs`,
`payment_events`.

- Деньги — целые копейки в `BIGINT`, без `float`.
- `payments.yookassa_payment_id` и `payments.idempotence_key` уникальны.
- Собранные суммы и рейтинг **вычисляются** из успешных платежей минус успешные возвраты,
  ручных счётчиков нет.
- Возвраты хранятся отдельно в `refunds` и уменьшают статистику и рейтинг после подтверждения.
- Рейтинг за месяц считается по дате успешной оплаты в часовом поясе `Europe/Moscow`.
- `payment_events` — журнал обработанных событий ЮKassa с уникальным ключом
  `payment:<id>:<status>` / `refund:<id>:<status>`.

### Как обрабатываются платежи

1. Бот создаёт запись `payments` (статус `new`) и только затем — платёж в ЮKassa с
   `Idempotence-Key`, `capture: true`, понятным назначением и `metadata`
   (`payment_id`, `fundraiser_id`, `user_id`). Сбои сети повторяются с тем же ключом.
2. Студент платит на странице ЮKassa. Возврат в бота **не** считается оплатой.
3. ЮKassa присылает уведомление на `https://<домен>/yookassa/webhook/<секрет>`.
   Сервер проверяет секрет в пути и IP-адрес отправителя, а затем **запрашивает платёж
   из API ЮKassa** — тело уведомления доказательством оплаты не считается.
4. Платёж блокируется (`SELECT … FOR UPDATE`), событие регистрируется в `payment_events`.
   Повторное уведомление — дубль, сумма не меняется.
5. Для `succeeded` сверяются сумма, валюта, `paid` и `metadata`. При расхождении платёж
   получает статус `review` и **не** учитывается — его видно в статистике админа.
6. Студенту приходит «Спасибо!» ровно один раз.

Подстраховка: кнопка «Проверить оплату» и фоновая сверка каждые `PENDING_SYNC_MINUTES`
минут запрашивают статус «зависших» платежей, если уведомление потерялось. Если ответ
на создание платежа потерялся, платёж находится по `metadata.payment_id`.

## Запуск на сервере (Docker Compose)

Нужны: VPS с Docker и Docker Compose, домен, указывающий на сервер, токен бота от
[@BotFather](https://t.me/BotFather).

```bash
git clone <репозиторий> studsbor && cd studsbor
cp .env.example .env
nano .env        # BOT_TOKEN, BOT_USERNAME, OWNER_TELEGRAM_IDS, POSTGRES_PASSWORD, DOMAIN
```

**HTTPS-сертификат** (один раз, до первого запуска Nginx; порт 80 должен быть свободен):

```bash
source .env
docker compose run --rm -p 80:80 --entrypoint certbot certbot \
  certonly --standalone -d "$DOMAIN" --email you@example.ru --agree-tos --no-eff-email
```

**Запуск:**

```bash
docker compose up -d --build     # миграции применяются автоматически (сервис migrate)
docker compose ps
curl https://$DOMAIN/health      # {"status":"ok"}
```

Откройте бота в Telegram и нажмите /start. Пользователи из `OWNER_TELEGRAM_IDS` получают
роль владельца и кнопку «🛠 Админ-панель». Общий фонд создаётся автоматически.

**Продление сертификата** — добавьте в cron (`crontab -e`):

```
0 4 * * 1 cd /path/to/studsbor && docker compose run --rm certbot renew --webroot -w /var/www/certbot && docker compose exec nginx nginx -s reload
```

**Обновление:** `git pull && docker compose up -d --build`.

**Логи:** `docker compose logs -f bot api` и файлы с ротацией в `logs/` (`bot.log`, `api.log`).

### Подключение ЮKassa

1. Получите `shopId` и секретный ключ в личном кабинете (для проверки — тестовый магазин).
2. Сгенерируйте секрет вебхука:
   `python -c "import secrets; print(secrets.token_urlsafe(32))"` → `YOOKASSA_WEBHOOK_SECRET`.
3. В кабинете ЮKassa → Интеграция → HTTP-уведомления укажите
   `https://<DOMAIN>/yookassa/webhook/<YOOKASSA_WEBHOOK_SECRET>` и включите события
   `payment.succeeded`, `payment.canceled`, `refund.succeeded`.
4. Заполните в `.env` `YOOKASSA_SHOP_ID`, `YOOKASSA_SECRET_KEY`, `RECIPIENT_NAME`
   и установите `PAYMENTS_ENABLED=true`; затем `docker compose up -d`.
5. Проведите тестовый платёж тестовой картой ЮKassa и проверьте, что пришло «Спасибо»,
   сумма появилась в «Отчётности» и рейтинге, а повторная отправка уведомления из
   кабинета ничего не меняет.

API-сервис не публикует порт наружу: доступ только через Nginx, который передаёт реальный
IP в `X-Real-IP`. Если ставите API без Nginx, выключите `YOOKASSA_CHECK_IP` или настройте
`REAL_IP_HEADER` — иначе заголовок можно подделать (сумма всё равно не засчитается без
подтверждения из API ЮKassa).

## Управление ботом (для администраторов)

Доступ к админке определяется по Telegram ID и роли в таблице `admins`, а не по username.

| Команда / кнопка | Что делает |
| --- | --- |
| `/admin`, «🛠 Админ-панель» | Панель администратора |
| `/stats` | Поступления, возвраты, расходы, остаток, плательщики, платежи на проверке |
| `/fund_create` | Пошаговое создание сбора: название → описание → цель (или «-») → срок ДД.ММ.ГГГГ (или «-») |
| «🎯 Управление сборами» | Открыть или закрыть сбор. Просроченные сборы закрываются автоматически ночью |
| `/expense_add` | Расход: сбор → сумма → назначение → чек (фото, файл, ссылка или «-») → дата |
| «👥 Участники» | Поиск по @username, Telegram ID или имени; карточка с суммой и последними взносами |
| `/export` | CSV платежей и расходов (разделитель `;`, открывается в Excel) |
| `/broadcast` | Рассылка объявления всем, кто не заблокировал бота (с предпросмотром) |
| `/payment <id>` | Подробности платежа (для разбора обращений) |
| `/refund <id> [сумма]` | Возврат платежа, полный или частичный — **только владелец** |
| `/cancel` | Прервать текущий диалог |

Роли: **owner** (задаётся в `OWNER_TELEGRAM_IDS`) назначает и снимает администраторов
(«👥 Участники» → карточка) и оформляет возвраты; **admin** — всё остальное.

Студенты видят чеки расходов в «Отчётности»: ссылку или команду `/receipt_<id>`,
которая присылает сохранённый файл.

### Напоминания

Каждый день в `REMINDER_HOUR` (по `TIMEZONE`) бот проверяет, кому пора напомнить:
не раньше `REMINDER_DAY` числа месяца, не чаще выбранной студентом частоты (каждый месяц
или раз в 3 месяца), новичкам — не в месяц регистрации. Под напоминанием есть кнопки
«Внести взнос» и «Больше не напоминать». Пока `PAYMENTS_ENABLED=false`, напоминания не
отправляются. Все отправки пишутся в `notification_logs`; заблокировавшие бота помечаются
и исключаются из рассылок.

### Резервное копирование

```bash
./scripts/backup.sh                               # backups/studsbor_<дата>.sql.gz, хранятся 30 дней
./scripts/restore.sh backups/studsbor_...sql.gz   # восстановление (заменяет текущие данные!)
```

Cron, ежедневно в 03:30: `30 3 * * * cd /path/to/studsbor && ./scripts/backup.sh`.
Копируйте `backups/` за пределы сервера (облако, другой сервер).

## Разработка

```bash
python3.12 -m venv .venv && source .venv/bin/activate
pip install -r requirements-dev.txt
pytest                                   # тесты на SQLite в памяти
TEST_DATABASE_URL=postgresql+asyncpg://user@localhost/studsbor_test pytest   # на PostgreSQL
ruff check .

# локальный запуск с PostgreSQL
export DATABASE_URL=postgresql+asyncpg://studsbor:studsbor@localhost:5432/studsbor
alembic upgrade head
python -m app.bot.main                              # бот
uvicorn app.api.main:app --port 8000                # вебхуки
```

Новая миграция после изменения моделей: `alembic revision --autogenerate -m "описание"`.

Тесты покрывают: разбор сумм, создание платежей, идемпотентность уведомлений (в т. ч.
параллельных на PostgreSQL), недоверие к телу уведомления, расхождение суммы, отмены,
возвраты, восстановление по metadata, рейтинги и границы месяца по Москве, расписание
напоминаний, вебхук (секрет, IP, 503 при недоступности ЮKassa) и сквозные сценарии бота
(оплата, меню, настройки, права администраторов).

## Юридические ограничения

Технически бот готов, но **до включения `PAYMENTS_ENABLED`** нужно решить:

- **Кто получатель.** Обычное физлицо не может подключить магазин ЮKassa — нужен ИП,
  юрлицо или подходящий самозанятый.
- **Самозанятость не подходит «по умолчанию».** НПД применяется к доходам от реализации
  товаров, работ, услуг; добровольный взнос без встречной услуги к ним автоматически
  не относится. Не оформляйте взносы как «оплату услуг», если услуги нет.
- **Пожертвования (ст. 582 ГК РФ)** — проверьте, кто вправе их принимать и как отчитываться.
- Наиболее прозрачный путь — согласовать схему с вузом (бухгалтерия, юридическая служба)
  или другой организацией-получателем и **письменно описать сценарий в ЮKassa**
  (добровольные взносы студентов в общий фонд и на проекты), получив подтверждение.
- **Чеки и фискализация (54-ФЗ)** зависят от согласованной схемы. Сейчас бот не передаёт
  данные для чека в ЮKassa; если схема требует чеков, нужно добавить объект `receipt`
  при создании платежа в `app/services/yookassa.py`.

Текст «Получатель средств» на экране подтверждения берётся из `RECIPIENT_NAME` — укажите
точное наименование получателя.
