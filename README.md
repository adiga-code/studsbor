# Фонд студсовета — Telegram-бот

Бот для добровольных взносов на нужды студенческого совета КБГУ: общий фонд и отдельные
сборы, оплата прямо в Telegram через ЮKassa (Telegram Payments), рейтинги участников,
ежемесячные напоминания и открытая отчётность о поступлениях и расходах.

> **Важно.** Приём реальных платежей выключен по умолчанию (`PAYMENTS_ENABLED=false`).
> Включайте его только после того, как согласованы получатель средств и правовая схема
> (см. «[Юридические ограничения](#юридические-ограничения)»). Всё остальное — сборы,
> отчётность, рейтинг, админка — работает и без платежей.

## Возможности (MVP)

| Раздел | Что есть |
| --- | --- |
| 💳 Внести взнос | Выбор общего фонда или проекта → произвольная сумма (или быстрые 100/300/500/1000 ₽) → счёт Telegram с назначением и получателем → оплата внутри Telegram → «Спасибо» в боте |
| 🎯 Наши сборы | Название, описание, цель, срок, собрано/потрачено, прогресс-бар, расходы по сбору |
| 🏆 Рейтинг | Топ-10 за календарный месяц (по Москве) и за всё время, своё место; анонимный показ по желанию |
| 📊 Отчётность | Сводка (поступления, возвраты, расходы, остаток), последние поступления, расходы с чеками, итоги по сборам |
| ⚙️ Настройки | Имя в рейтинге, анонимность, напоминания вкл/выкл, частота (раз в месяц / раз в 3 месяца), история своих взносов |
| 🛠 Админ-панель | Статистика, создание/закрытие сборов, расходы с чеками, участники и роли, CSV-выгрузка, рассылка, учёт возвратов |

Не входит в первую версию (по ТЗ): автоплатежи, уровни и достижения, веб-панель, мультивалютность.

## Архитектура

Бот работает в одном из двух режимов с одним и тем же кодом:

| | Бесплатно: Vercel + Supabase | Свой сервер: Docker |
| --- | --- | --- |
| Как бот получает сообщения | вебхук: Telegram вызывает функцию `/api/telegram` | long polling |
| Регулярные задачи | Vercel Cron раз в сутки (`/api/cron/daily`) | APScheduler внутри процесса |
| База | Supabase (PostgreSQL) | PostgreSQL в Docker |
| Стоимость | 0 ₽ в пределах бесплатных тарифов | VPS от ~200–300 ₽/мес |

Оплата в обоих режимах идёт через Telegram Payments: ЮKassa подключена к боту в @BotFather.

```
app/
  config.py            настройки из переменных окружения / .env
  money.py             разбор и форматирование сумм (копейки)
  db/                  модели SQLAlchemy 2, подключение (в т. ч. к пулеру Supabase)
  services/            бизнес-логика без Telegram:
    payments.py          счета, проверка перед оплатой, учёт оплат и возвратов
    stats.py             рейтинги, суммы, отчётность
    fundraisers.py, expenses.py, users.py, notifications.py, export.py
  bot/                 Telegram-интерфейс: handlers/, клавиатуры, тексты,
                       storage.py — состояния диалогов в базе
  jobs.py              напоминания, закрытие просроченных сборов и устаревших счетов
  web.py               режим вебхука: /api/telegram, /api/cron/daily, /api/setup
  scheduler.py         планировщик для режима polling
index.py, vercel.json  точка входа и cron для Vercel
supabase/schema.sql    схема базы одним SQL-файлом (запасной вариант для Supabase)
migrations/            Alembic
tests/                 pytest (SQLite или PostgreSQL)
```

### База данных

`users`, `fundraisers`, `payments`, `refunds`, `expenses`, `admins`, `notification_logs`,
`payment_events`, `fsm_states` (состояния диалогов бота).

- Деньги — целые копейки в `BIGINT`, без `float`.
- `payments.invoice_payload` (идентификатор счёта) и `payments.telegram_payment_charge_id`
  уникальны; `provider_payment_charge_id` — номер операции в ЮKassa для сверки.
- Собранные суммы и рейтинг **вычисляются** из успешных платежей минус успешные возвраты,
  ручных счётчиков нет.
- Возвраты хранятся отдельно в `refunds` и уменьшают статистику и рейтинг.
- Рейтинг за месяц считается по дате успешной оплаты в часовом поясе `Europe/Moscow`.
- `payment_events` — журнал обработанных оплат с уникальным ключом
  `tg:<telegram_payment_charge_id>`.
- На всех таблицах включён Row Level Security без политик: в Supabase это закрывает их
  от публичного REST API. Бот подключается владельцем таблиц, на него RLS не действует.

### Как обрабатываются платежи

1. Студент выбирает сбор и сумму. Бот создаёт запись `payments` (статус `new`) с уникальным
   `payload` и выставляет счёт (`sendInvoice`) с назначением, получателем и пометкой
   «добровольный взнос, не оплата услуг».
2. Перед списанием Telegram присылает `pre_checkout_query`. Бот проверяет: счёт наш и
   принадлежит этому студенту, ещё не оплачен и не устарел (`INVOICE_TTL_HOURS`), сумма
   и валюта совпадают, сбор открыт. Иначе — отказ с понятной причиной. Если бот не
   ответил за 10 секунд (например, выключен), Telegram сам отменит оплату — деньги не спишутся.
3. После оплаты приходит `successful_payment` — только он означает, что деньги получены.
   Сообщение приходит от серверов Telegram, подделать его нельзя. Если бот был выключен,
   Telegram доставит его после запуска (обновления хранятся до 24 часов).
4. Оплата блокирует строку платежа (`SELECT … FOR UPDATE`) и регистрируется в
   `payment_events`. Повтор того же события — дубль, сумма не меняется, второго «Спасибо» нет.
5. Если сумма не совпала со счётом, платёж получает статус `review` и не учитывается —
   его видно в статистике админа. Если тот же счёт оплачен второй раз, деньги учитываются
   отдельной записью, чтобы отчётность совпадала с выпиской ЮKassa.

Неоплаченные счета старше `INVOICE_TTL_HOURS` ночью помечаются устаревшими.

**Возвраты.** Telegram Payments не умеет возвращать рублёвые платежи. Возврат делается в
личном кабинете ЮKassa (номер операции — в `/payment <id>` и в CSV), после чего владелец
отмечает его в боте командой `/refund`: статистика и рейтинг уменьшаются, студент получает
уведомление.

## Бесплатный запуск: Vercel + Supabase

### 1. База в Supabase

1. Создайте проект на [supabase.com](https://supabase.com) (бесплатный тариф). Регион —
   **Central EU (Frankfurt)**, запомните пароль базы.
2. **Connect** (вверху проекта) → вкладка **Connection String** → **Session pooler** →
   скопируйте строку и подставьте пароль вместо `[YOUR-PASSWORD]`:
   `postgresql://postgres.<id>:<пароль>@aws-0-eu-central-1.pooler.supabase.com:5432/postgres`

   Нужен именно **Session pooler**: прямое подключение (`db.<id>.supabase.co`) работает
   только по IPv6, которого нет на Vercel. Transaction pooler (порт 6543) тоже поддерживается.

### 2. Проект на Vercel

1. **Add New → Project** → импортируйте репозиторий. Vercel сам найдёт `index.py`.
2. **Settings → Environment Variables** (для Production):

   | Переменная | Значение |
   | --- | --- |
   | `BOT_TOKEN` | токен бота от @BotFather |
   | `BOT_USERNAME` | имя бота без @ |
   | `DATABASE_URL` | строка Session pooler из Supabase |
   | `OWNER_TELEGRAM_IDS` | ваш Telegram ID (узнать: @userinfobot) |
   | `WEBHOOK_SECRET` | случайная строка из букв, цифр, `_` и `-` |
   | `CRON_SECRET` | ещё одна случайная строка |
   | `RECIPIENT_NAME` | наименование получателя средств |
   | `PAYMENT_PROVIDER_TOKEN` | токен ЮKassa из @BotFather (сначала Test) |
   | `PAYMENTS_ENABLED` | `true`, когда готовы принимать взносы |

   Случайную строку можно получить так: `python -c "import secrets; print(secrets.token_urlsafe(32))"`
   или любым генератором паролей (без спецсимволов, кроме `_` и `-`).
3. Регион функций — **Frankfurt (fra1)**, он уже задан в `vercel.json`. Это рядом с базой,
   чтобы бот успевал подтвердить оплату за отведённые Telegram 10 секунд.
4. Cron работает только для **production**-деплоя. Production-ветка задаётся в
   **Settings → Git** (обычно `main`) — слейте туда изменения или укажите свою ветку.
5. Сделайте **Redeploy**, чтобы переменные окружения применились.

### 3. Подключение бота

Откройте в браузере `https://<ваш-проект>.vercel.app/api/setup?key=<WEBHOOK_SECRET>`.
Страница применит миграции (создаст таблицы), создаст общий фонд и зарегистрирует вебхук.
Ответ должен содержать `"migrations": "ok"` и `"status": "Готово: напишите боту /start"`.

Если миграции не применились, откройте в Supabase **SQL Editor**, вставьте содержимое
`supabase/schema.sql`, нажмите **Run** и снова откройте ссылку `/api/setup`.

После каждого обновления схемы базы (новые файлы в `migrations/versions`) откройте
`/api/setup` ещё раз. Повторный вызов безопасен.

### Ограничения бесплатных тарифов

- **Cron на Vercel Hobby — раз в сутки**, около 12:00 МСК (точность — в пределах часа).
  Этого достаточно для напоминаний и ночной уборки.
- **Функция работает не дольше 300 секунд.** Рассылка `/broadcast` успевает примерно
  на 2–3 тысячи человек. Напоминания укладываются в 200 секунд; кому не хватило времени,
  получат их на следующий день.
- **Supabase приостанавливает бесплатный проект после недели без активности.** Ежедневный
  cron обращается к базе, так что этого быть не должно. Если проект всё-таки «уснул», его
  включают в панели Supabase. Объём базы на бесплатном тарифе — 500 МБ, для бота это много.
- **Тариф Vercel Hobby предназначен для некоммерческого использования.** Студенческий
  фонд под это подходит, но условия лучше перечитать.
- **Пулер Supabase:** соединение шифруется, но сертификат сервера не проверяется.
- Логи — в панели Vercel: **Deployments → Functions / Logs**.
- **Резервные копии:** в бесплатном Supabase их нет. Периодически выгружайте `/export`
  или делайте дамп: `pg_dump "<строка Session pooler>" > backup.sql`.

**Не запускайте одновременно** Docker-версию и Vercel с одним токеном. Docker-бот при старте
снимает вебхук, а `/api/setup` его снова ставит, поэтому работать будет тот, кто запущен последним.

## Запуск на сервере (Docker Compose)

Альтернатива бесплатному варианту — без ограничений по времени и с локальными
резервными копиями. Нужны: любой сервер (VPS) с Docker и Docker Compose и токен бота от
[@BotFather](https://t.me/BotFather). Домен и HTTPS не нужны.

```bash
git clone <репозиторий> studsbor && cd studsbor
cp .env.example .env
nano .env        # BOT_TOKEN, BOT_USERNAME, OWNER_TELEGRAM_IDS, POSTGRES_PASSWORD
docker compose up -d --build     # миграции применяются автоматически (сервис migrate)
docker compose ps
```

Откройте бота в Telegram и нажмите /start. Пользователи из `OWNER_TELEGRAM_IDS` получают
роль владельца и кнопку «🛠 Админ-панель». Общий фонд создаётся автоматически.

**Обновление:** `git pull && docker compose up -d --build`.

**Логи:** `docker compose logs -f bot` и файл с ротацией `logs/bot.log`.

### Подключение оплаты

1. В @BotFather: ваш бот → **Bot Settings → Payments** → **ЮKassa Test**. Пройдите
   подключение в боте ЮKassa и вернитесь — BotFather покажет токен вида `381764678:TEST:…`.
2. Впишите его в переменные окружения (`.env` или настройки Vercel):
   `PAYMENT_PROVIDER_TOKEN=…`, `PAYMENTS_ENABLED=true`, а также `RECIPIENT_NAME` —
   точное наименование получателя. Перезапустите бота: `docker compose up -d` или Redeploy на Vercel.
3. Проверьте в боте: взнос тестовой картой ЮKassa (`5555 5555 5555 4477`, любой срок в
   будущем и любой CVC) → «Спасибо», сумма в «Отчётности» и рейтинге; отказ при закрытом
   сборе; отметка возврата через `/refund`.
4. Когда схема согласована (см. ниже), подключите **ЮKassa Live**, замените токен на боевой
   (`…:LIVE:…`) и перезапустите бота. Тестовые платежи останутся в базе — перед запуском
   их можно удалить, создав базу заново или очистив таблицы платежей.

Минимальная сумма: Telegram не выставляет счёт меньше своего минимума (около 1 $ в рублях,
зависит от курса). Если `MIN_AMOUNT_RUB` окажется ниже, студент увидит «Не удалось
выставить счёт» — поднимите значение.

**Чеки (54-ФЗ).** Если по согласованной схеме нужны чеки, включите `RECEIPT_ENABLED=true`
и проверьте `RECEIPT_VAT_CODE`, `RECEIPT_PAYMENT_SUBJECT`, `RECEIPT_PAYMENT_MODE` с
бухгалтерией. Telegram будет запрашивать e-mail плательщика и передавать его и состав
чека в ЮKassa; в кабинете ЮKassa должна быть подключена онлайн-касса.

## Управление ботом (для администраторов)

Доступ к админке определяется по Telegram ID и роли в таблице `admins`, а не по username.

| Команда / кнопка | Что делает |
| --- | --- |
| `/admin`, «🛠 Админ-панель» | Панель администратора |
| `/stats` | Поступления, возвраты, расходы, остаток, плательщики, неоплаченные счета, платежи на проверке |
| `/fund_create` | Пошаговое создание сбора: название → описание → цель (или «-») → срок ДД.ММ.ГГГГ (или «-») |
| «🎯 Управление сборами» | Открыть или закрыть сбор. Просроченные сборы закрываются автоматически ночью |
| `/expense_add` | Расход: сбор → сумма → назначение → чек (фото, файл, ссылка или «-») → дата |
| «👥 Участники» | Поиск по @username, Telegram ID или имени; карточка с суммой и последними взносами |
| `/export` | CSV платежей и расходов (разделитель `;`, открывается в Excel) |
| `/broadcast` | Рассылка объявления всем, кто не заблокировал бота (с предпросмотром) |
| `/payment <id>` | Подробности платежа и номера операции в ЮKassa и Telegram |
| `/refund <id> [сумма]` | Отметить возврат, уже сделанный в кабинете ЮKassa (полный или частичный) — **только владелец** |
| `/cancel` | Прервать текущий диалог |

Роли: **owner** (задаётся в `OWNER_TELEGRAM_IDS`) назначает и снимает администраторов
(«👥 Участники» → карточка) и отмечает возвраты; **admin** — всё остальное.

Студенты видят чеки расходов в «Отчётности»: ссылку или команду `/receipt_<id>`,
которая присылает сохранённый файл.

### Напоминания

Каждый день в `REMINDER_HOUR` (по `TIMEZONE`; на Vercel — по cron около 12:00 МСК) бот
проверяет, кому пора напомнить:
не раньше `REMINDER_DAY` числа месяца, не чаще выбранной студентом частоты (каждый месяц
или раз в 3 месяца), новичкам — не в месяц регистрации. Под напоминанием есть кнопки
«Внести взнос» и «Больше не напоминать». Пока оплата не включена (`PAYMENTS_ENABLED`
и `PAYMENT_PROVIDER_TOKEN`), напоминания не отправляются. Все отправки пишутся в `notification_logs`; заблокировавшие бота помечаются
и исключаются из рассылок.

### Резервное копирование

```bash
./scripts/backup.sh                               # backups/studsbor_<дата>.sql.gz, хранятся 30 дней
./scripts/restore.sh backups/studsbor_...sql.gz   # восстановление (заменяет текущие данные!)
```

Cron, ежедневно в 03:30: `30 3 * * * cd /path/to/studsbor && ./scripts/backup.sh`.
Копируйте `backups/` за пределы сервера (облако, другой сервер).

## Разработка

```bash
python3.12 -m venv .venv && source .venv/bin/activate
pip install -r requirements-dev.txt
pytest                                   # тесты на SQLite в памяти
TEST_DATABASE_URL=postgresql+asyncpg://user@localhost/studsbor_test pytest   # на PostgreSQL
ruff check .

# локальный запуск с PostgreSQL
export DATABASE_URL=postgresql+asyncpg://studsbor:studsbor@localhost:5432/studsbor
alembic upgrade head
python -m app.bot.main                    # режим polling
uvicorn index:app --port 8000             # режим вебхука, как на Vercel
```

Новая миграция после изменения моделей: `alembic revision --autogenerate -m "описание"`.

Тесты покрывают: разбор сумм, параметры счёта и чека, проверки перед оплатой (чужой,
устаревший, оплаченный счёт, неверная сумма, закрытый сбор), однократный учёт оплаты
(в т. ч. параллельной доставки на PostgreSQL), повторную оплату счёта, расхождение суммы,
возвраты, рейтинги и границы месяца по Москве, расписание напоминаний и сквозные сценарии
бота (счёт → pre_checkout → оплата → рейтинг → возврат, меню, настройки, права).

## Юридические ограничения

Технически бот готов, но **до включения `PAYMENTS_ENABLED`** нужно решить:

- **Кто получатель.** Обычное физлицо не может подключить магазин ЮKassa — нужен ИП,
  юрлицо или подходящий самозанятый.
- **Самозанятость не подходит «по умолчанию».** НПД применяется к доходам от реализации
  товаров, работ, услуг; добровольный взнос без встречной услуги к ним автоматически
  не относится. Не оформляйте взносы как «оплату услуг», если услуги нет.
- **Пожертвования (ст. 582 ГК РФ)** — проверьте, кто вправе их принимать и как отчитываться.
- Наиболее прозрачный путь — согласовать схему с вузом (бухгалтерия, юридическая служба)
  или другой организацией-получателем и **письменно описать сценарий в ЮKassa**
  (добровольные взносы студентов в общий фонд и на проекты), получив подтверждение.
- **Подключение ЮKassa через @BotFather юридический вопрос не снимает**: магазин оформлен
  на конкретного получателя, и деньги приходят ему.
- **Чеки и фискализация (54-ФЗ)** зависят от согласованной схемы — см. `RECEIPT_ENABLED`.

Текст «Получатель средств» в боте и в счёте берётся из `RECIPIENT_NAME` — укажите
точное наименование получателя.
